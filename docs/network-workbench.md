# 网络检测与验机工作台

本次实现覆盖用户清单第二部分 4–9。所有源码、协议适配、界面及测试用例先集中完成；本文件写入时没有运行测试、构建、格式检查、网络拨测或实机工具。统一整合后由主任务运行验证、修复失败范围，再创建整体 PR。源码实现不能替代实机验收或工具许可。

## 来源、权限与任务

入口 `/api/network-workbench`；独立 UI 位于 `web/src/network-workbench/NetworkWorkbench.tsx`。`router()` 返回 `Router<AppState>`；后台每五秒调用 `tick(&state)`。清单、目标、许可工具、资料源、方案、任务、报告、分享及本地配对都有实际接口。只有经过授权的管理员会话能提交排队方案；来源服务器、接收端及反向执行端分别授权，后台每次执行重新核对当前权限。API 令牌读请求仍取管理员与令牌的权限交集。

方案冻结服务器集合、目标及参数，按成功依赖顺序运行，支持失败终止、手动暂停/恢复、并发来源上限、定时与错过窗口只补一次或跳过。对同机任务复用共用服务互斥。派发后先用任务 metadata 恢复尚未关联的 job，防止掉线或事务中断后重复创建任务。队列、运行、清理、请求取消、真正取消和失败分开展示；没有新数据不会变成成功。

## 逐项交付边界

“源码已实现”表示真实 API、参数校验、执行/导入路径与界面已经写入；并不表示下面所列工具已在真实服务器验收。所有 Agent 工具必须先提供完整签名制品与对应架构的离线清单，保持现有诊断签收顺序。

|---|---|---|
| 4 统一探测来源 | 面板、指定服务器与固定集合，报告记录 source/target | Agent 能力及授权缺失会暂停 |

## 离线工具供应

`tools/network_workbench_artifact.py` 仅接收已安装且事先审批摘要的离线 inventory，不下载工具。inventory需包括 schema=1、engine_version=1.0.0、固定 `/usr/bin/python3` 解释器摘要；每个实际工具的绝对路径、sha256、version、license、source_url、licensed=true；磁盘测试需 allowed_test_directories，smartctl需 allowed_health_devices，业务保护可用 protected_processes。打包脚本读取版本输出并固化摘要，生成的tar仍需既有正式签名发布流程签名。尚未准备合格制品时，共用诊断服务会暂停方案，不能把目录登记当作工具安装完成。

测试源码包括模型保护边界、DNS异常报文/压缩循环、离线摘要与许可、到期授权及完整启动门禁。集中验证中，Python网络执行器16项、离线制品6项、核心边界8项离线测试通过，执行器与制品脚本语法检查通过；工具身份调用使用模拟，fio只检查4096字节自有匿名测试文件，没有运行真实吞吐或硬件负载。Rust及浏览器验证单独记录。仍需独立验收双端iperf3端口释放、fio强制取消文件释放、HTTP3工具能力、IPv6来源、异常服务暂停及有效授权供方接口；不得在生产服务器反复高负载验机。

覆盖复审新增同连接HTTP阶段计时与4个回环fixture源码、真实iperf3区间曲线及边界/方向测试源码，并将CPU硬配额与CPU争用权重分离。此轮Python网络16项、制品6项、核心边界8项受影响范围已集中通过；新增Rust/前端源码由主任务集中复验；回环fixture不连接外部服务，不代替真实TLS/双端吞吐验收。
