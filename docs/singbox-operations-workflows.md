# sing-box 运维与代理用户流程

本记录对应任务第四部分 14、15。本轮功能源码已冻结，集中执行发现的失败已修复并通过受影响复验。首轮 Rust 工作区结果为 1201 通过、9 失败、25 忽略；用受影响目标的复验结果替换后，119 个工作区结果组汇总为 1216 通过、0 失败、25 忽略，没有重复累加已通过目标。最终前端全量测试为 173 通过、0 失败，TypeScript/Vite 构建通过并生成 35 个 dist 文件。最终整体结果以 [本轮验收记录](acceptance/operations-platform-expansion.md) 为准；本记录不表示真实设备、ACME 签发或完整商业工具执行已验收。

入口保持为“代理节点 → 部署与运行时运维”和“代理用户”。新增迁移、备选及分批发布在服务器运维详情中，用户诊断、延期、额度重置、连接凭据轮换、客户端模板在用户详情中；批量策略组分配在用户列表上方。代理用户自助入口继续使用独立 Passkey 会话。

## 主要 API

- `POST /api/plugins/sing-box/operations/preview`：七类操作的固定对象预览。
- `POST /api/plugins/sing-box/operations/{id}/apply`：管理员会话再验证后确认，状态变化则拒绝。
- `GET /api/plugins/sing-box/users/{id}/diagnosis`：授权来源、套餐、部署、批次、轮换、审计与能力限制。
- `GET/PUT /api/plugins/sing-box/users/{id}/client-template` 与 `POST .../compatibility`：有版本的完整客户端模板及兼容查询。
- `POST /api/plugins/sing-box/servers/{id}/operations-view/checkpoint`：请求目标 Agent 主动核对实际配置与进程，结果未回报前保持待确认。
- `POST /api/plugins/sing-box/servers/{id}/operations-view/preflight` 与 `POST .../preflight/confirm`：完整只读预检与再次验证确认；确认后继续已保存普通节点目标的正常发布，实际应用等待 Agent 回执。
- `POST .../preflight/bootstrap`：仅没有任何 sing-box 部署时，依据本人最新固定预检、真实特权目录/系统后端及本机统计端口证据，再验证后明确创建空运行时目标；已有部署不能覆盖。
- `GET /api/plugins/sing-box/servers/{id}/operations-view`：当前服务器的部署条件、差异、偏差、路径和历史。
- `GET/POST /api/plugins/sing-box/runtime-rollouts`、`POST .../{id}/advance`、`.../pause`、`.../members/{server}/inspect`：固定版本分批对账、确认与暂停。
- `GET /api/plugins/sing-box/runtime-inventory`：真实本地已签名版本/平台/摘要与每个候选的兼容结论；不会把远端版本声明当本地库存。
- `GET/PUT /api/plugins/sing-box/operations/privacy`：分别设置审计保留；订阅 0 天表示停止记录。

预览保存敏感状态的摘要，不保存原始凭据。应用记录在同一业务事务内写入；高风险操作使用平台最近五分钟的会话证明，目标服务器逐台授权。每台服务器实际执行状态保留为排队、等待设备或已确认，不用 HTTP 保存成功替代实际结果。

旧用户列表、详情、创建/更新响应与访问授权列表在只读权限、API 令牌或证明过期时隐藏订阅地址/令牌与连接 UUID。诊断始终只返回授权和状态。管理员完整订阅接口要求 `proxy:write` 和五分钟内交互式证明；既有订阅弹窗使用平台统一再次验证重试。客户端模板普通读取隐藏自定义 DNS headers 等敏感字段，编辑前通过 `?reveal=true` 受控读取完整模板并保留版本，保存同样要求证明。各次实际披露均写入元数据审计，节点只读视图原有投影不包含私钥、密码或 psk。平台守卫对节点、直接/外部授权和订阅重置的密钥写操作同样要求再次验证。

发布循环按每一轮真实套餐状态、链路生命周期、来源更新、链路发布与配置发布返回值写入 `sing-box` 系统心跳；审计清理每三十秒运行，失败持续保留在聚合状态直到重试成功。来源字段只保存有界阶段名称，不在系统自检中泄露原始错误和敏感参数。

## 完整普通节点部署预检

迁移 0055 保存元数据快照、业务摘要、明确的两项 Agent 请求编号、面板 DNS/证书证据、五分钟有效期和确认主体；不保存节点密钥、订阅令牌或私钥内容。最新预检按数据库单调序列选择，同一秒的连续请求不会因为随机 UUID 选错记录。读取每一项时返回 `state`、`blocking`、`observed_at`、`source`、`evidence` 与下一步原因。Agent 回执没有到达时显示排队/已分发，超时保持未知；不以 HTTP 入队成功或人工核对结束替代实际 Agent 证据。预检历史按平台 audit 与插件管理员保留策略的较短值清理。

只读采集需要该服务器 `proxy:write`、`operations:read`、`monitoring:read`、`diagnostics:write` 的管理员会话；API 令牌不能授权延迟执行。确认另需近期交互式密码/TOTP 证明。Agent 专用能力 `fleet:runtime-preflight:v1` 与面板、Agent 本机 `runtime_inspection` 均默认不开启。面板“服务器 → 运维 → 资产与授权”有独立授权开关，不因插件启用自动授权。目标权限检查不创建文件、不修改服务、不读取秘密文件内容。

自动证书的“签发准备条件”只在固定 1.14.2 编译器确实生成 Let’s Encrypt ACME 提供方、SNI 域名、联系邮箱、HTTP-01/TLS-ALPN-01 挑战与节点引用，且所有当前证据依赖均通过后满足。HTTP-01/TLS-ALPN-01 都使用 TCP 80/443 挑战，Hysteria2/TUIC 的业务健康握手仍使用 QUIC。编译成功不代表外部挑战已经可达；面板解析来源、端口空闲证据与 CA 的实际访问分别说明。首次签发仍可能因为网络、CA 策略或限流失败，不能用准备条件称为证书已签发。

通用 Agent `RuntimePermissions` 以文件描述符和 no-follow 实际检查 `runtime_root/{module}@main`、其 `data` 与 `data/certificates`；后两者对应真实启动 `-D data` 与编译后的 `data_directory=certificates`。目录缺失时只检查最近已有父目录能否读取、写入和遍历，不创建目标；现存子目录的符号链接或权限异常会阻塞 `acme_storage`，根目录可写不能掩盖子目录异常。过期、缺字段及缺回执保持未知。

运行时权限来自注册描述符实际 `sinan-singbox@main.service` 的已加载 User/Group、NSS UID/GID 和补充组，并通过降权只读采集实际目录访问。业务根目录要求真实运行时账号可读、可遍历；ACME 持久目录另要求该账号可写。特权 root 可访问不等于运行时可访问；没有已加载服务或账号未知时保持未知，不回退为 root。已有监听所属 PID 也从此实际 unit 获取。

明确启用插件后，未创建有效业务监听的服务器会先正常安装空配置。若在首次空安装前已有有效节点授权，普通形状门禁会等待真实账号证据；此时可在完整预检内选择“首次安装空运行时”。它只允许无任何部署、模块目标/应用记录一致的服务器，使用本人当前五分钟内的预检、真实特权目录/系统后端安装权限、空配置统计端口无冲突、生命周期、能力及签名平台制品。只生成无业务监听和凭据的确定性空配置、冻结签名制品并通知 Agent，保留完整业务目标 dirty；不使用未知运行时账号证明业务权限。并发与重复请求在服务器锁内拒绝已有部署，失败只按既有固定部署重试入口处理。空安装会使原预检失效，等待 Agent 安装及健康回执后，必须重新采集完整预检才能发布业务。

面板系统解析器最多读取 33 个结果，识别超过 32 的截断而不据前 32 个宣布通过；全部返回地址逐 A/AAAA 核对，同族有一个错误地址即失败，返回族没有登记依据时为未知。ACME 验证域名另要求本次返回公网地址。没有某族回答不会冒充该族已可用，也不宣称所有权威解析器已核对。

"自动证书入口的当前证书观测"和"已部署 TLS 握手"在首次部署前可保持非阻塞未知，绝不改成成功；后续近期、当前证书版本的真实公网握手才作为面板观测依据。当前入口已有受信任证书，也可能来自先前或人工签发；该观测不证明本次目标运行时的 ACME 签发已完成，`issuance_owner_confirmation` 保持未知，`certificate_issued` 不伪造成功。已有适配器在实际应用后等待最多 240 秒签发并执行本机 TCP TLS 或 QUIC 的信任链/SNI 握手及统计接口健康检查，失败使该次部署失败；这不替代公网来源可达性验收。

普通节点的新版本候选批次只在当前指纹一致、五分钟内、阻塞项全部通过且已明确确认时分发；超时或业务/能力/制品/策略变化要求重新采集确认。普通节点保存先登记目标草稿，publisher 在新增有效监听或改变监听、协议、TLS、服务设置等部署形状时使用同一门禁，缺少确认则回滚发布事务并保留 dirty 等待。第一次有效授权开始监听也属于新增部署；既有监听内的用户凭据变更、撤销、停用和删除继续自动发布，以便额度保护和安全撤销及时生效。链路节点继续使用原有候选门禁；配置包相同的元数据更新不要求重新预检。确认会重新标记 dirty 触发发布，publisher 还会核对确认主体当前是否仍有相应服务器权限，并复核当前指纹、全部证据和五分钟时效。旧 publisher 的既有应用检查、原生配置检查和链路门禁保持；已稳定失败的固定部署重试沿用自己的原有不可变身份/互斥条件。实际公网入口连通和 TLS 握手仍分别验收，手工证书预检只证明当前材料可用，不能声称已保存到目标机器。

源码回归用例覆盖监听名字不能替代 PID、端口证据截断/过期保持未知、非 root 服务管理授权未知、通配符只覆盖单层域名、首次 TCP/QUIC 签发准备与当前证书观测分离、错误提供方/节点引用不可被旧握手覆盖、证书存储/DNS/旧快照缺失阻塞、多地址同族错误、未登记另一地址族与 DNS 截断。它们已纳入集中执行，修复后的受影响补验通过，最终结果统一见验收记录；真实 systemd/OpenRC 特权后端、NAT 映射、证书签发及目标设备回执须在隔离环境签收。

`crates/panel/tests/deployment_preflight.rs` 的五个 PostgreSQL/HTTP 完整场景在首轮集中执行和受影响补验中均全部通过：新普通监听未确认/过期保持 dirty 且不发布；同秒两个真实请求按提交顺序只确认最新；配置材料改变与确认主体撤权都不能复用旧确认；同监听凭据替换、真实流量账本耗尽与最后授权撤销继续自动发布；首次空安装保留业务目标，拒绝重复空安装并要求全新业务确认。它们复用明确的 TEST_ONLY 签名惰性制品和有界 DNS/权限观测，确实经过预检 API、设备任务分发/回执、确认与原发布事务，没有生产门禁开关或直接写入成功状态；这些场景不证明真实公共 DNS、证书签发或原生服务已执行。
