# ADR 0081：固定目标运维编排、证据驱动故障与独立恢复

状态：已实现并完成集中本地验证；生产与设备签收条件保持。日期：2026-10-03。

## 背景

本轮授权清单第五部分要求批量任务、告警协作、恢复工具和云费用对照。已有远程命令、诊断取消、通知渠道及阿里云官方适配可复用，但“加一个入口”不能代替真实执行、进程停止回执或恢复演练。

## 决定

1. 运维方案只接收固定类型的系统快照、服务状态／启停／重启、签名失败部署重试和首步面板完整备份，拒绝任意 shell 文本。快照与服务步骤转换为 `fleet::Operation`，经 Agent `Privileged`／`ServiceManager` 执行。部署仅重新应用已发布失败的固定 sing-box 1.14.2 配置，冻结配置与制品身份，保留现有签名和运行时门禁，并结合实际部署回执与新 checkpoint 核对结果。备份每个任务只执行一次，冻结已有计划配置并在首台步骤前取得真实恢复点。与执行记录在同一数据库事务中保存任务步骤，避免面板断线后重复派发。服务权限取面板策略与 Agent 本机策略交集；部署及备份分别重新核对代理与全局恢复授权。
2. 提交目标为有序不可变服务器集合，首台独立作为试运行批次。依赖成功才进入下一步，下一批只有前批全部成功且必要的人工确认完成才开始。服务器行锁和持久化互斥锁阻止同机冲突任务；未知交付结果保留锁，不重放动作。
3. 确认执行、计划启用、恢复操作要求近期管理员会话认证。任务创建中的 API 令牌可产生预览，但不能代替会话证明。定时和自动处置每次触发、每一步执行都重新核对管理员功能及服务器授权，授权撤销后停止新派发。
4. 自动处置只支持有新观测的受管服务故障，明确固定目标、步骤、冷却、最大次数和人工暂停。它不根据无数据判断恢复，也不允许在未知结果上重复动作。
5. 故障事件保留来源键、原始证据、观测时间、确认人、分派、备注及恢复依据。关联表示相关证据，不宣称确定根因。维护继续记录指标和事件，只抑制计划内通知；已有 Telegram／Webhook 渲染和投递代码供本模块专用 outbox 复用。
6. 定时和任务首步完整备份实际执行固定 `pg_dump` 和 `age`。数据库导出采用 `REPEATABLE READ` 的 `pg_export_snapshot`；永久制品目录持有现有 `release_permits` 写互斥，排除 ACME 临时材料和备份暂存目录。全局数据库咨询锁阻止备份重叠，未知执行必须先核对停止与清理，不能重试。清单记录固定镜像、客户端／服务器版本、数据库迁移校验、材料散列和需要的外部密钥版本；解密主密钥不打包。执行成功才登记完成，失败或重启中的未知执行留错误并暂停，不虚构备份成功。任务引用的恢复点在任务结束前受保留和退役保护。
7. 官方 PostgreSQL 16 `pg_dump` 和发行版 `age` 是新增的系统工具依赖，复用现有 Rust 压缩、tar、SHA-256 和进程能力，不引入新的备份 Rust 依赖。相比自行实现数据库逻辑导出，官方工具能够保留完整对象定义、序列和恢复语义；工具大版本必须与服务匹配。
   导出目标取运行中连接池的实际 `PgConnectOptions`，而不是把 URI 填入不会展开 URI 的 `PGDATABASE` 默认值。密码、TLS 文件和有效连接参数通过受控子进程环境传递，命令行仅包含转义的数据库名；保留查询参数、环境及 pgpass 已经确定的语义，禁止子进程重新选取其他 pgpass 凭据。失败反馈只含固定工具阶段与退出码，避免记录数据库 URI 或工具原始错误中的秘密。
8. 独立恢复工具不依赖面板 API，在全新 Docker 项目进行真实数据库恢复和本机健康检查。内部网络隔绝生产 DNS／云／通知访问，恢复数据库后暂停计划、关闭通知和云自动控制。只有完成恢复及健康检查才形成通过的报告；演练精确清理自建资源，不使用全局 prune。默认不覆盖生产数据。
9. 每家云提供方独立展示真实能力。本模块关联阿里云 ECS／EIP 台账、采购信息和原币种账单，保存官方缓存的变化及时间；Hetzner Cloud 通过固定官方 REST v1 入口、受限分页与超时读取服务器清单，仅完整读取可确认资源缺席。两家都支持凭据中心引用和按关联服务器过滤历史；Hetzner 不伪造账单、Robot 或远端写能力。阿里云写操作继续使用已有预览、请求身份、人工暂停和未知结果只读核对流程；费用缓存不能成为实时硬限额。
10. 阿里云账号优先保存集中 `cloud` 凭据引用，每类官方调用执行前取用加密材料，只产生局部签名对象。引用停用或解密失败不会回落旧密钥；既有旧明文账号保留明确兼容模式，迁入引用时清除原明文字段。后台心跳记录真实周期结果和错误，但不将执行器周期正常解释为远端资源健康。
11. 计划退订提醒只针对显式开启的费用台账记录，不执行退订动作。每个记录形成唯一站内事件，维护规则控制通知投递；重新启用不重复提醒。供应商质量对照只聚合有授权的自有 Telemetry、历史诊断条件和原币种采购成本，缺失观测保持未知，不插值可用率或推导统一排名。
12. 阿里云 ECS 安全组变更限定为已登记 VPC 实例与普通组的成员关系，复用官方 ECS 签名客户端，不引入新依赖。全局账号读取与全部当前 / 历史关联服务器授权共同约束，写入只允许原发起管理员近期会话证明。固定五分钟成员 / 规则 / revision / 关联快照；每步在同账号互斥下重新读取成员和本步完整策略指纹，包括内网访问策略，保留全部原有基线，附加组必须明确 Accept，先加入并核对再移除确认受管且策略未变的组。意图先持久化，官方写入不重试；超时或无法确认成员保留未知并阻止后续，新的只读核对与实际人工停止证据只能结束流程、不能将原未知改写为成功或失败。没有后台重放器，隔离恢复冻结运行中请求。组内规则、企业组与费用报价无实际支持时明确不可用 / 未知；保留基线不能保证任意管理连通。

## 限制与签收

完整验机门禁、工具许可、真实云写入与生产恢复边界不变。集中验证覆盖数据库迁移、权限撤销、任务未知结果、维护抑制、恢复依赖、工具失败及隔离演练，结果以实际日志与恢复报告为准。恢复相关脚本 23 个受控用例通过严格 ResourceWarning 检查；最终源码配套二进制实际完成周期完整备份与双目标任务只执行一次备份，随后恢复并核对 57 项迁移和启用、停用加密凭据。错误同 ID 密钥导致隔离启动失败，正确材料取得实际 AES 认证健康确认；缺少认证证据的报告不被登记为恢复通过。

运行二进制及全部 35 个内嵌前端文件与最终构建制品逐一配对。健康证据来自隔离容器回环，宿主端口不可达；本机动态库兼容测试镜像不替代生产 Docker 全量构建验收。测试材料和所属资源精确清理，仅保存有界结果及对应身份。开发期间不调用真实云资源写入、生产恢复或真实通知；目标 Agent 操作仍需设备签收。结果见[集中验收记录](../acceptance/operations-platform-expansion.md)。
