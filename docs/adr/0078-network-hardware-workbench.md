# ADR 0078：网络检测、硬件验机与结构化报告工作台

日期：2026-10-03。状态：源码实施，统一验证及专用设备签收待完成。

## 背景与决定

本次用户授权范围覆盖网络检测、路径、吞吐、硬件、出口资料与综合报告。旧 MVP 排除项不再限制这些授权，但共用诊断任务的资源保护、制品签名、取消清理、工具许可及 NodeQuality 完整启动门禁继续适用。工作台入口不能将 NodeQuality 完整模式改成若干名称后绕过旧工具链禁用条件。

新增 `network_workbench`，使用类型化方案、步骤、来源、目标和预算；不是任意 JSON 配置仓库，也不是远程 shell。服务器组在提交时冻结为明确的服务器 ID 集合。每个来源、双端接收方及反向路径执行端单独核对管理员服务器权限。后台每次推进重新核对当前管理员权限；API 令牌不能变成继承所有者权限的排队或定时任务。

低开销面板 TCP、HTTP 与外部 IP 资料查询由面板执行。Agent 项目经过现有 `diagnostics::service::create_job`，供给登记的 `network-workbench` 版本 1.0.0 制品；`WorkbenchAdapter` 仅转换冻结参数、预检离线供应、收集报告。共用 Agent worker 持有生命周期、systemd 资源隔离、互斥、持久化取消和完成确认。

不新增依赖。独立适配器放在现有 adapter-tcpquality crate 内作为 companion，其描述符与旧 TCP 插件分开。离线工具入口使用宿主 Python 标准库，固定 `/usr/bin/python3`，同时校对签名清单中的解释器与工具摘要、许可、版本输出和原始来源。禁止运行期间下载安装、脚本融合、自发公开排名上传或修改宿主系统配置。Python 增加了一项实际平台依赖，因此没有合格解释器及离线清单时明确阻止执行；不声称所有 Agent 平台都具备能力。

## 执行与报告

目标登记必须明确自有或获准依据及有效期。HTTP、WebSocket、QUIC URL 须属于选定目标，同目标重定向有上限。UDP 必须提供有效请求和预期响应；无响应记为未知。QUIC 使用签名清单中的 HTTP3 curl，预检其 HTTP3 特性，执行 `--http3-only`，保留有效参数和握手/错误证据；不降级成 HTTP2 或拿通用 UDP 请求代替 QUIC。

路径分别保存实际路由与外部资料。未知 ASN、反向解析及地理位置保留为空。正式接口资料或获准报告可导入，默认不抓取网站。双向诊断在两个实际执行端分别运行；单向结果不能推出反向路径。

吞吐先启动单次、有限时长的 iperf3 监听，读取属于该进程的内核监听 inode 证据，再安排客户端。每流速率、流数、时长及双向发送量共同检查预算；显式保存 sender、receiver、direction。客户端不可用、工具失败或连接超时不自动重复具有副作用的监听动作。监听自身有 deadline，取消转发给所有已派发子任务，等待共用服务的进程/挂载清理确认。

磁盘验机只使用明确目录中自行创建的测试文件。文件创建后取消目录链接，子进程仅继承受控文件描述符，fio 打开 `/proc/self/fd/<fd>`；即使强制终止整个 cgroup 也不会留下有名字的测试文件，不涉及原始磁盘写入。只读 smartctl 设备另用签名清单 allowlist，不与写入工具共享设备范围。

Speedtest 的工具不能承诺精确流量硬上限，预算保护下不启动其 Agent 执行；合法外部原始结果可导入。Geekbench 同样支持有许可确认的结果导入，保留大版本并拒绝跨版本统一评分。导入带来源、参数、时间、原始输出与环境，不获得 Agent 真实清理/实机签收身份。

报告分享使用随机 bearer 凭据、散列存储、有效期与撤销，默认不包含地址、设备身份、授权依据、凭据或原始日志。完整报告只在经过来源集合授权的管理员入口导出。指标比较必须匹配工具、版本、目标与参数；跨服务器来源单独显示，绝不合成与条件无关的速度分数或超售结论。

## 后续签收边界

源码登记、隔离自动验证、专用服务器工具验收及正式发布分别记录。当前不能通过工作台解除已有 NodeQuality 门禁。CPUWeight仍只表示争用权重；独立CPU百分比预算使用实际systemd CPUQuota/cgroup硬上限，无法证明上限时预检拒绝。面板HTTP阶段已来自同一次HTTP/1.1请求的实际连接；工具平台差异、外部数据接口授权及需要凭据的远端代理链出口绑定等边界在[工作台清单](../network-workbench.md)中逐项列出。集中验证、实际失败修复与条件未执行项见[本轮验收](../acceptance/operations-platform-expansion.md)。
