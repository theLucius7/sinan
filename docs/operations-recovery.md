# 运维、故障、备份恢复与云资源

本模块实现本轮清单 16–19 的共享任务和恢复入口。新增源码、协议、界面及必要测试用例先集中实施，再按用户要求统一验证、测试和迭代。开发环境的真实执行证据与仍需目标设备签收的能力分别记录。

## 自动化与批量任务

面板「运维、故障与恢复 → 自动化与维护」先选择服务器，再设置固定步骤。系统快照只读；服务状态、启动、停止、重启通过目标 Agent 的 `ServiceManager` 执行。面板与 Agent 都须明确授权服务名；模板不接受命令字符串。

方案还可加入签名部署重试和面板恢复点。部署步骤只重新应用已经发布、已经失败的固定 sing-box 1.14.2 配置与签名制品，不生成新业务配置；预览冻结每个目标的版本、配置身份和失败候选。后台及 Agent 交付前分别核对代理授权、运行时能力和原有签名门禁，实际部署回执与新的相同配置 checkpoint 共同决定结果。交付后的未知状态不自动重新部署。

面板备份只允许作为方案首步，选择已经保存的备份计划，并冻结其接收方和保留设置。每个任务只调用一次真实完整备份执行器；成功恢复点由所有固定目标引用，不能按服务器重复备份。只有实际加密材料、清单、散列和清理结果均成功后才进入首台步骤。全局恢复权限、所有目标权限和备份设置在执行前再次核对；执行器持有全局互斥，未知执行保留恢复保护，既不重试也不提前清理恢复点。人工结束未知备份需要近期会话验证、最近十分钟核对证据及停止／清理确认，原执行结果仍保留未知。

执行预览保存服务器集合、步骤和参数的散列，十分钟内确认。提交后不会随着服务器组、标签或筛选变化扩大目标。首台独立完成后再执行固定批次，每台每一步都保留原生执行回执。选用批次确认时，前批全部成功才允许确认下一批；任一步失败即停止后续步骤。

互斥锁一直保留到设备确认结束。尚未交付的操作可以取消，已经交付的受限服务动作暂不支持可靠运行中取消。请求取消与进程停止分开显示；超时或断线记为未知，不自动重新执行。服务动作人工解除锁需要近期会话验证、确认进程已停止及最近十分钟的实际核对证据，原动作成功与否仍保留未知。未知部署先从任务详情发起专用只读 checkpoint，再提交其编号和人工结论；只有新的真实 Agent 证据与原配置、制品、当前目标和时间一致，才记录人工结束并停止后续步骤。原部署回执仍保留未知；此核对不把人工结论改成 Agent 成功，也不重新部署。

定时计划保留周期、显示时区偏移、错过窗口策略和最大次数。`skip` 跳过超出一分钟的窗口；`run_once` 最多补一次，之后直接定位未来窗口。已有同计划任务未结束时跳过新窗口。自动处置只针对受管服务的新故障观测，保留冷却、最大次数和人工暂停；未知执行不触发重试。

每次触发及每一步执行检查当前管理员权限。API 令牌只可产生预览；执行确认、计划和自动处置启用使用近期管理员会话证明。任务详情中的服务回执还需要各目标的 `services:read`，部署证据需要各目标代理读取权限，完整备份证据需要全局 `recovery:read`。自动处置仅接受快照和受管服务步骤，不能自动触发部署或完整备份。

## 告警与事件

已有服务器告警关联到故障事件，不重复发送原通知。受管服务健康／配置偏差、任务积压、备份失败及云预算／到期分别保留明确来源。相同来源聚合展示，不自动推断根因。

证书签发／续期故障由真实 `network_acme_jobs` 最新失败或未知回执桥接到 `certificate:<id>` 故障来源，记录工具版本、错误码、签发任务、时间和完整关联服务器范围。同一任务不重复提醒；仅更新的真实已签发、已保存且有效版本回执才自动恢复，排队、人工核对或无新数据不能恢复，更不推断已部署或握手成功。沿用故障通知outbox与关联服务器维护抑制；读取和分派同时检查网络台账及完整历史范围。

处理人可确认、分派、添加备注、调整升级提醒和导出含证据的故障报告。恢复必须有更新的健康状态、任务终结回执、实际成功备份，或人工提供的最近实际检测结果。任务退出积压不表示任务业务成功，执行状态在恢复证据中单独保留。没有新数据时不自动恢复。

维护窗口保留监测和故障记录，可分别停止新任务和抑制通知。通知复用 Telegram／Webhook 渲染与投递，独立 outbox 保留失败、重试及取消状态。开发期间不投递真实通知。

计划退订提醒读取服务器费用台账 `kind=cancellation` 的 `valid_until`，日期含义为计划退订生效时间。未配置或没有明确日期时不发送日期提醒；在自动化页为每条记录显式开启并选择提前一小时至三十天。配置需要管理员会话，API 令牌不能提交此延迟计划；配置者权限在触发时重新核对，撤权后暂停。每个记录只建立一个站内提醒事件，不因停用／再启用、人工确认或恢复事件而重发，也不自动升级此日程提醒。`notified_at` 是站内事件记录时间，渠道送达需看事件真实投递结果；维护窗口仍抑制投递。此流程不退订云资源、不停服、不撤销 Agent，也不付款。

## 定时完整备份的实际执行

面板备份计划调用真实工具，不能只依赖登记清单。标准镜像提供与 PostgreSQL 16 配套的官方 `pg_dump` 和 `age`。原生部署可用 `SINAN_BACKUP_PG_DUMP` 指定可信绝对路径；工具大版本必须与数据库一致。

数据库导出使用当前连接池已经确定的主机或 Unix socket、端口、账号、数据库、TLS 文件、会话选项与应用名，保留 SQLx 对查询参数、环境默认及 pgpass 的实际解析结果。数据库密码只传入该子进程的受控环境，命令行只有经过转义的数据库名；不把含密码 URI 放进命令行，也不让子进程另外读取可能已变化的 pgpass。数据库导出与 age 加密分别显示固定工具阶段和退出码，不回显连接 URI、密码或原始工具错误输出。

部署需明确配置：

- `SINAN_BACKUP_PANEL_IMAGE`：对应面板源码的完整 sha256 镜像身份。
- `SINAN_BACKUP_POSTGRES_IMAGE`：数据库的完整 sha256 镜像身份。
- `SINAN_BACKUP_DIR`：受限存储目录，可为独立异地存储的挂载；未配置时为面板本机私有目录，不宣称异地保护。
- `SINAN_BACKUP_KEYRING_REFERENCE`：解密主密钥环的独立保管位置。清单只有位置及所需密钥 ID，不包含主密钥值。

计划选择独立保管方的 age 公钥，后台对数据库取得导出快照，锁定不可变签名制品存储，然后实际 `pg_dump`、打包、加密。成功的备份记录包含明文材料与加密归档散列、迁移校验、实际工具版本及恢复材料范围。暂存文件以 600／700 权限保存并在完成后删除；失败不产生“已备份”的状态。面板重启遇到未确认的备份暂停计划并保留核对提示。

本轮永久面板文件为 `artifacts/releases`，采用与制品下载写入相同的互斥锁；ACME 工作目录是临时秘密材料，持久账户和私钥已加密保存在数据库，不能把工作目录复制当作可恢复证书备份。节点关键数据不属于面板完整备份，可使用 `scripts/node-backup.py` 按面板与 Agent 文件权限交集选择 1–32 个必要文件、逐文件获取 typed 回执并校验 hash，再用独立 age 公钥加密。每文件上限 256 KiB，总量 8 MiB；保存各文件读取时间，不宣称多个运行中文件具有事务一致性。未知文件任务不自动重发，也不复制 Agent 身份。

保留策略按每个计划独立计算，只有在份数和日期同时超过配置、没有活动依赖、未处于保留期限时才清理本执行器命名且位于精确备份目录内的加密文件。台账退役不删除用户提供的外部存储。最新必要备份和恢复点依赖受保护。

## 独立校验、解密和隔离恢复

现有 `scripts/panel.py backup` 在停止同一面板容器的窗口创建完整恢复点，清单格式 2 增加镜像、数据库版本、迁移校验及外部密钥版本。工具保留原数据库和身份，备份后启动原容器，不自动应用新镜像。

示例路径均为占位符。先保存到私有目录，再使用独立工具：

```bash
python3 scripts/panel.py backup
python3 scripts/recovery.py verify --backup /私有备份/恢复点 --report /私有报告/完整性.json
python3 scripts/recovery.py encrypt --backup /私有备份/恢复点 --recipient age1公钥 --output /独立存储/恢复点.age
python3 scripts/recovery.py decrypt --backup /独立存储/恢复点.age --identity /私有密钥/age身份 --output /私有恢复/材料
python3 scripts/recovery.py drill --backup /私有恢复/材料 --keyring-file /私有密钥/凭据密钥环.json --report /私有报告/演练.json
```

age 身份文件与凭据密钥环文件必须为权限 600 的普通文件。密钥环格式是 `{"current":"当前密钥ID","keys":{"密钥ID":"32字节密钥的base64"}}`；此文件独立保管，不能加入普通备份清单或提交仓库。

恢复工具拒绝重复 JSON 字段、无效编码、非 32 字节密钥和缺失版本，并把恢复数据库中的实际密钥版本与清单逐一核对。隔离副本在启动监听和后台任务前使用这些密钥验证所有启用及停用凭据的 AES 认证；相同版本 ID 搭配错误密钥也会停止启动。只有真实认证完成才返回恢复专用健康确认，报告写入 `keyring_authenticated`。含加密凭据的恢复点不能仅凭普通健康响应或密钥 ID 相同就登记为恢复通过。

节点必要文件可独立保存，读取前需在两端授权允许目录和文件大小，并使用有 `files:read` 及明确服务器范围的管理员会话；将实际 `sinan_session` cookie 值保存在权限 600 的私有文件。异步设备操作会再次核对当前权限，API 令牌不能代替此会话：

```bash
python3 scripts/node-backup.py --origin https://panel.example.com --session-file /私有密钥/文件读取会话 --server 服务器编号 --file /允许目录/配置.json --file /允许目录/证书.crt --recipient age1公钥 --output /独立存储/节点关键数据.age
```

工具不跟随携带会话的重定向、不读取未明确选择的目录，也不根据任务超时重新提交。Agent 身份材料不应加入节点业务文件选择。原运行数据如需要应用一致性，先安排明确维护或服务停止窗口，再读取并分别保留每个文件的时间。

`verify` 验证材料 hash、必要文件、固定镜像和归档边界，拒绝路径穿越、链接、设备文件以及不完整材料。它只证明完整性，不证明已经恢复。

`drill`／`restore` 要求本机已经有清单记录的固定镜像，不自动拉取浮动标签。格式 1 旧备份缺少数据库镜像时，需要明确指定 `--legacy-postgres-image` 并另行核对版本。工具只创建全新 `sinan-recovery-` 项目，拒绝任何同名容器、卷和网络；在内部网络执行实际 `pg_restore`、迁移身份核对、数据库大版本核对、解密密钥材料检查及本机健康检查。数据解包通过明确命名和所属标记的辅助容器执行，启动超时也保留可清理记录。恢复后的副本冻结任务和日程、DDNS、自动证书续期、通知与云自动控制，注销旧会话并撤销副本内管理 API 令牌；阿里云安全组变更中的运行中请求保留为未知，不能继续原写操作。原备份和生产环境不受修改。已有运行中或未知的外部动作仍需人工核对，内部网络阻止生产外联。

演练结束精确清理自建资源，清理失败写入报告。健康检查先从主机回环访问；若 Docker 内部网络的端口映射无法从主机访问，则在所属面板容器内实际请求回环健康接口，并分别记录 `panel_health_source` 与 `host_loopback_reachable`。容器内正常不等于主机入口可达；这种环境仍需独立核对本机访问路径。`restore` 保留成功创建的隔离环境供进一步查看；它不是自动覆盖生产数据的命令。恢复报告可导入面板，并分别显示清单登记、完整性证据和真实恢复证据；导入来源标记为外部工具报告，不伪造面板重复执行。

灾难恢复到新的正式主机时，先完成上述隔离演练，再核对固定版本、独立密钥、面板 HTTPS 地址、Agent 信任关系和服务入口，明确关闭旧面板执行器后迁移。实际切换生产地址及恢复已有生产卷未在本轮执行，也不自动复制 Agent 身份。

## 云资源与费用

云台账允许没有 Agent 的资源。阿里云 ECS 固定公网入口和独立按量 EIP 复用已有官方查询及变更能力；Hetzner Cloud 通过官方 REST v1 提供真实只读服务器清单。每家提供方单独展示能力，面板关联已有云资源到明确服务器，记录订单参考、采购金额、预算、币种、到期和备注。

资源历史保留查询来源、时间、原快照与新快照。公网地址、带宽、计费方式、状态及官方错误分别变化，不把资源查询失败当成资源必然被删除。费用按原币种分列，不把缺少币种转换为零成本。预算提醒只使用六小时内的明确账单缓存，保留查询时间和账单延迟说明；不执行实时消费硬停机。

阿里云账号新建默认引用凭据中心用途为 `cloud` 的 UUID，秘密结构为 `provider: alicloud`、`access_key_id`、`access_key_secret`。每次查询、账单、变配或启停调用之前解析加密引用，停用、用途不符、缺少历史解密密钥和字段异常明确失败，不能退回旧密钥。解析只产生局部签名材料，编辑或后台更新不会回写明文。已有旧账号可明确保留兼容模式；列表和编辑器均不回显密钥，迁入引用时清空原明文字段。云调度心跳记录实际周期结果、错误及来源，不代表远端资源全部健康。

真实启停、带宽及计费操作复用阿里云插件的官方预览、版本检查、请求身份、未知结果只读核对和人工暂停。开发期间不调用真实云写操作。

Hetzner 新建账户仅接受凭据中心 `cloud` 引用，秘密结构为 `{"provider":"hetzner","api_token":"受限令牌"}`，列表不回显秘密。显式刷新只请求固定 `https://api.hetzner.cloud/v1/servers`，每页 50 台、最多 10 页／500 台；单页响应最多 2 MiB、单请求 15 秒、总计 120 秒，拒绝重定向。账户管理与读取全量清单需要全局云权限，已关联资源的清单、详情与历史按服务器授权筛选；关联修改同时核对旧、新服务器并要求近期真实会话证明。账户已产生资源后不能更换为另一项目的凭据引用，以免同号资源被误接管；密钥轮换使用原凭据条目。

阿里云安全组入口管理已登记 VPC ECS 与普通安全组的成员关系，读取官方 `DescribeInstances` 和 `DescribeSecurityGroupAttribute`，预览明确当前组、目标组、新增 / 移除、保护基线与费用未知。它不编辑组内规则，也不支持企业组；读取截断、类型 / VPC 不符或附加组存在非明确 Accept 策略时拒绝。全部原有非本流程受管的组保持为基线，只有本流程真实加入并记录规则指纹、且当前规则未变的附加组允许移除；保留基线不能保证所有管理连接始终可用。

安全组官方账号读取要求全局 `cloud:read`，写入还要求 `cloud:write`、全部当前及固定历史关联服务器范围、原发起管理员会话和近期再次证明；API 令牌不能确认延迟写入。预览五分钟有效，固定账号 / 资源 revision、服务器关联时间、成员及规则摘要；确认重新读取同一官方状态。每步在账号互斥锁内重新核对当前成员和该组完整规则指纹，先加入并真实读取确认，再移除受管附加组。`JoinSecurityGroup` / `LeaveSecurityGroup` 每步仅提交一次，返回请求编号和真实复核结果；原始意图先持久保存，账号凭据替换和资源重新关联在运行中 / 未知状态时阻塞。

安全组超时、响应缺失、接受后成员未吻合或读取失败保留 `unknown`，后续步骤停止，不自动重试或盲目回退。没有后台写操作恢复器；进程重启后的 `running` 必须由原管理员实际确认原请求结束、记录有界证据，再通过新的官方只读读取核对，转为 `reconciled` 并保留原 `unknown`。这能说明核对时的成员关系，不能推出超时请求曾失败。回归使用回环官方协议 mock，不向真实云账号发出变更。

只有完整读取才能更新完整清单时间、确认资源未在本次清单中出现。分页不完整、限流、凭据停用或请求失败保留已有快照，显示未知及实际错误；六小时后明确标为缓存过期。停用账户只是本地管理动作，保留历史，不停止或删除远端服务器。Hetzner 的账单、余额、电源、带宽、安全组变更与 Robot 专用服务器在此适配器中明确不可用。

云费用页提供供应商观测对照，`GET /api/operations/suppliers?from=秒&until=秒` 按当前 `fleet_profiles.asset.provider` 分组，窗口最长 365 天，最多 256 台已授权服务器及 2000 个诊断记录，截断状态明确返回。历史供应商变更未冻结，迁移前的历史证据不能自动归因当前供应商。每台服务器还需 `servers:read`，监控与诊断数据分别需要对应读取能力。原币种成本只计算窗口内实际登记的采购、续费和退款，不把价格变化记录再次当作付款。

在线证据来自实际接收的 Telemetry 历史。页面计数“有样本的服务器小时槽”：每台每个 UTC 小时有真实采样才计一次；缺失小时保持无证据，既不解释为离线，也不插值成持续在线或可用率。样本数为完整窗口聚合桶的下界，至少跨一天且有 24 个证据小时槽才显示已有长期观测。诊断仅在固定工具制品、插件版本、参数、资源预算和历史预检证据一致时分组；来源身份分别保留，原始结果通过报告编号核对。缺少工具身份、执行环境或两台已成功且清理确认的报告时标为不足。供应商对照不生成一次性排名、统一速度／硬件分数或“超售”结论。

集中验证的恢复、节点备份和独立观察点脚本共通过 23 个受控用例，启用严格 ResourceWarning 检查；覆盖真实 age 加解密、本机 HTTPS 握手、读取回执完整性、未知任务不重发、异常输出清理与归档保留保护。

最终源码配套二进制完成真实定时完整备份、任务首步备份及双目标去重：两台没有 Agent 的测试服务器共享同一次完整备份回执，没有模拟设备执行。清单与实际 PostgreSQL 恢复均核对 57 项迁移身份，备份包含通过真实 API 创建的启用和停用加密凭据。相同密钥 ID 的错误内容阻止隔离面板启动；正确密钥完成两类凭据的实际 AES 认证及恢复专用健康确认。真实演练报告被登记为恢复通过，缺少材料认证证据的负面报告保留为未通过，并非 HTTP 拒绝导入。

最终运行容器的二进制散列与构建身份一致，实际读取的全部 35 个内嵌前端文件与当前制品逐一相符。演练健康来源为隔离容器回环；宿主回环端口不可达，不能据此签收宿主入口。测试兼容镜像使用本机编译产物和对应动态库，不能替代生产 Docker 全量构建验收。所属测试容器、卷、网络、数据库、随机密钥、明文恢复材料和旧兼容镜像在保存有界结果后精确清理；真实 Agent 服务操作、云资源写入、生产恢复及真实通知未在开发环境执行。最终结果与源码身份见[集中验收记录](acceptance/operations-platform-expansion.md)。
