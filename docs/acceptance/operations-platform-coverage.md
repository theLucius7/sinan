# 平台扩展：21 类需求的源码覆盖与验收条件

审阅日期：2026-10-03。本文对照用户的 21 类清单、实际后端、前端入口和执行器记录交付范围。它是 PR 的源码映射，不是实机成功报告；集中验证结果由 [本轮验收记录](operations-platform-expansion.md) 保存。本次复审没有运行测试、构建、格式工具，也没有执行外部服务写入或服务器负载测试。

表中的“实现”要求存在参数校验、权限检查、实际执行或明确获准的导入路径及状态反馈。登记工具、保存配置、提交队列、导入报告与目标设备执行成功分别记录；工具、许可或正式门禁尚未满足时不能记为验收通过。

## 复审发现的真实缺项与当前状态

复审曾明确指出通用服务器业务迁移、普通节点完整部署预检、同请求 HTTP 阶段、吞吐曲线、CPU 硬预算、真实服务退出与证书失败事件、typed 部署 / 单次备份及中断核对、长表单保护，以及官方云安全组变更的缺项。这些项目已补入上表所指的实际入口与源码，不再用采集复制、原始 JSON、权重、台账、配置或文档代替要求的行为。

最终业务迁移由 `0056_network_server_migrations.sql` 保存冻结预览与历史；安全组由 `0057_alicloud_security_groups.sql` 保存原始意图、逐步官方证据、附加组归属与未知核对。

普通节点发布门禁位于 `plugins/singbox/panel/publisher.rs` 创建新部署前，配置包相同的元数据更新提前返回；有效普通节点与未清理链路节点分别处理。`runtime/preflight.rs` 在确认和实际发布时复核当前授权、节点 / 有效用户、平台 / 能力 / 策略、登记入口 / 关联证书版本与签名制品，最新记录由 0055 单调 `sequence` 选择。首次空安装 `preflight/bootstrap.rs` 只提交空标准配置、固定制品和等待 Agent 状态，不把账号缺失按 root 业务权限通过。`crates/panel/tests/deployment_preflight.rs` 的数据库 / HTTP fixture 覆盖未确认、过期、同秒最新选择、材料 / 管理员权限变化、同形状凭据与额度安全撤销及首次空安装，五个场景在首轮集中执行和受影响补验中均全部通过；这些模拟观测不能代替真实设备签收。集中验证与修复后结果见 [本轮验收记录](operations-platform-expansion.md)，本次源码复审不将正式工具 / 实机门禁改成验收通过。特别是 NodeQuality 完整工具与启动验收能力仍明确待完成。

## 执行条件与待验能力

- 网络与验机执行要求真实固定版本、签名、许可、支持平台、本机受限策略、CPU/内存/I/O 等硬资源保护及取消清理能力。没有制品或无法证明 CPU 硬上限的平台明确拒绝派发；许可确认或工具台账不是成功执行证明。
- **NodeQuality 完整验机仍未通过其工具供应和完整启动验收门禁。** 本轮综合方案保持该门禁，不能通过选择其他入口绕过。Speedtest / Geekbench 当前完成的是许可内原始结果导入，受管商业工具执行不可用。
- Agent PTY、systemd 服务、fio / 双端 iperf3、HTTP3、IPv6、隧道 / WireGuard、socat、sysctl / nft、证书文件部署 / 服务恢复等有真实执行实现，尚须获准隔离设备分别签收。明确实际回执前不声称进程已停、文件已清理或端口已释放。
- 四家 DNS、IP 供应方、云 API、Cloudflare DNS-01 / Let's Encrypt、通知、OSV 和独立观察点有来源接口与错误语义；真实外部写操作、投递或异地观测没有因为开发 fixture 而完成。各来源缺失、过期、失败与冲突保留。
- 备份恢复要求真实独立加密目标、age 身份、历史 credential keyring、固定应用 / PostgreSQL 版本和必要制品。隔离演练成功只证明对应材料与环境；开发兼容镜像不是生产镜像全部平台验收。整体切换须按手册核对新入口、Agent 信任与服务关系。

## 明确的实现范围，不能误列为用户硬缺口

完整 VT / 全屏终端模拟器、录屏、大文件或续传、全舰队 WireGuard 自动编排、周期自动恢复演练、自动覆盖生产卷、自动生产地址切换、任意运行时跨版本升级、任意客户端模板、所有 provider 相同变更能力和所有对象统一导出契约，都超出了该清单明列的具体要求。它们应在相应入口说明支持范围，不能据此否定已实现的实时 PTY、有界传输、成员配置、真实隔离演练、受控迁移、明确版本兼容或按提供方实际能力提供的操作。

用户明说“不支持的项目明确不可用”的逐用户限速 / 连接限制，以及允许合法执行或导入的 Geekbench，不应被改写成假成功，也不应被误判为必须实现任意 runtime 不具备的能力。相反，明确要求的业务迁移、完整预检、真实同请求 HTTP 阶段、吞吐曲线、硬预算、事件来源和长表单保护不能仅以文档披露替代实现。
