# 2026-10-03 重新架构阶段二：订阅抓取合一

这是重新架构的第二个大步骤，起点是阶段一提交 `f6d5cd2`。设计、范围调整和理由见 [ADR 0079 阶段二实施说明](../adr/0079-rearchitecture-plugins-sources-chains.md)和[待定问题记录](../open-questions.md)。

所有修改先集中完成并冻结，然后统一验证。远端 CI 继续暂停，未触发、重跑或恢复。没有访问真实订阅来源、真实设备或生产面板，也没有签署、发布或部署。

## 修改内容

- **共享抓取器 `plugins/singbox/panel/subscription_fetch.rs`：**
  - 两套订阅来源唯一的下载实现，以有序来源（B）的可替换网络层和 20 秒总期限为基础，规则取两边并集。
  - 对数字编号来源（A）是新增的限制：
    - 地址必须以 `https://` 开头、无首尾空白、端口不为 0。
    - 认证内容不能只含空白或控制字符，长度按“名称加内容”合计 8 KiB。
    - 只跟随 301/302/303/307/308，其余 3xx 按 HTTP 失败处理。
    - `application/xhtml+xml` 按 HTML 拒绝；`Content-Length`、`Content-Encoding` 不可读时明确失败。
    - 解压受总期限约束。
    - 缓存标记上限 2 KiB；超限的旧标记在请求前丢弃，改为完整下载。
  - 对有序来源（B）是新增的限制：
    - 拦截 `.internal` 主机名；整个 `3fff::/16` 都视为非公网。
    - 支持 deflate，`Accept-Encoding` 改为 `gzip, deflate`。
    - 内容类型中任何位置出现 `text/html` 都按 HTML 拒绝。
    - 连接超时不超过 10 秒。
- **适配层：**
  - `sources/fetch.rs`（A）保留调用方式、默认请求标识、`subscription-userinfo` 流量解析和全部 `ImportError` 代码。
  - `subscription_sources/fetch.rs`（B）保留请求与结果类型，以及已存失败的 `stage/kind/message`。
  - 两者都用编译期断言确认正文上限与共享抓取器一致。
- **测试：**
  - 原 B 的抓取测试移入共享模块，改为断言共享失败类型。
  - 新增用例：`.internal`、`3fff::/16`、请求标识、过期缓存标记、deflate、非标准 3xx、多种 HTML 内容类型、无效长度声明、多段 gzip 夹带超限内容、附加凭据前的同源检查。
  - 每个适配层都有逐项映射测试，确认对外错误码和失败分类不变。
- **解析器：** 未合并。两套解析器在 YAML 标量、合并键、格式识别、URI 参数、名称规则和输出模型上有语义差异，统一后会让部分已存订阅生成新版本或刷新失败，因此移入阶段三。

## 未验证范围

- 远端 CI 继续暂停，本地结果不代表 main 全绿。
- 没有向真实订阅服务发起请求。新的限制只在模拟网络和本机回环 TLS 上验证。
- 新限制可能让少数原本能刷新的来源失败，例如：返回非标准 3xx、只返回 `application/xhtml+xml`、`Content-Length` 不规范、URL 带首尾空白的 A 来源。没有在生产数据上统计受影响的来源。
- 解析器合并和来源模型统一属于阶段三，需要详细迁移方案和单独授权。
