# DNS、证书与服务器网络配置

此文对应用户清单第 10–13 组。源码与界面已进入根任务集中验证及失败修复阶段，最终结果以[本轮验收记录](acceptance/operations-platform-expansion.md)为准；尚未执行真实 DNS/服务器操作。配置已保存、提供方已接受、Agent 已执行与真实观察成功是不同状态。

## DNS 与 DDNS

DNS 功能保留在 DDNS 插件。账号引用凭据中心的 `dns` 条目，不把秘密发给 Agent；分别配置提供方、区域和服务器范围。账号检查按官方接口读取允许区域。

| 清单项目 | 实际实现与行为 |
| --- | --- |
| 账号与记录 | Cloudflare、阿里云 DNS、腾讯 DNSPod、华为云 DNS 的官方查询、新建、修改和删除；账号启停、范围与连接检查 |
| 变更预览 | 五分钟一次性持久预览，固定账号版本、原始记录和期望参数；应用前再次读取完整远端快照 |
| 地址来源 | 手工、Agent 地址、指定网卡、公网发现分别选择并保存来源；旧 Agent 未提供细分字段时明确不可用 |
| 双栈 | A/AAAA 配置关联、事务创建，但同步和错误分别展示；单个手工地址不会虚构另一族 |
| 冲突与接管 | 记录身份、线路、同名 CNAME、重复规则、受管标记核对；接管须显式，普通记录编辑拒绝启用的 DDNS 和 ACME 专属记录 |
| 历史与失效 | 候选、原值、远端快照、核对时间和错误；离线、地址缺失、陈旧或凭据失效保持现有解析；规则删除仍保留历史 |
| 批量迁移 | 服务器、提供方、域名、账号、启停的完整差异；固定规则版本及服务器集合，一次事务，身份变化清理旧记录关联，不复制旧提供方秘密 |
| 回退 | 已确认历史与远端值精确匹配后做逆变更；外部修改拒绝；DDNS 回退暂停自动同步 |
| 解析观测 | 指定 IPv4/IPv6 解析器，真正 UDP 查询及同解析器 TCP 截断回退，保存返回码、值、TTL、耗时和期望集合 |

提供方分别声明实际支持的记录类型、线路、结构字段、备注或记录集合；不支持参数直接拒绝。异步受理与未知结果只读核对，不自动重放。未知新建没有返回记录标识，即使远端有同值也不认领或回退删除。DDNS 首次创建没有旧值，不能使用值回退；普通记录已确认新建可按历史逆向删除。迁移不隐式删除原提供方记录，应另行预览清理。

DDNS 系统自检心跳仅说明真实调度迭代健康，单规则结果看规则及历史，不声称所有 DNS 更新成功。

## 域名与证书

域名台账关联服务器、DNS 规则、应用和维护方。证书台账保存覆盖域名、签发方、维护责任方和明确服务目标。导入接口只接受公开 PEM，检查有效期及 SAN；不同版本保留公开指纹和有效期，回退仅改变期望版本，部署另行确认。

DNS-01 自动签发使用签名库存里的固定版 lego。面板保存计划，选择 Cloudflare DNS 凭据、联系邮箱、Let's Encrypt 生产或预发布环境、许可和服务条款、续期窗口。自动续期是明确授权：没有证书时允许首次签发，进入窗口时签发新版本。后台冻结域名/证书版本并重新核对管理员、服务器和 DNS 权限，缺制品、密钥环、DNS 授权或平台支持时拒绝，不能用 PATH 上的未知二进制替代。

账户材料和私钥进入加密凭据中心；普通列表、回执、审计和日志不返回私钥。工具在独立 0700 工作区执行，秘密只在进程环境和受控文件中存在，标准输出/错误不采入普通日志。正常完成清理临时工作区。超时或中断显示未知，并要求核对签发方和遗留 TXT；重发前人工确认，不自动重复下单。

同样提供外部维护方 DNS-01 挑战辅助：只创建、核对与清理标记专属的 Cloudflare TXT，保留其他 TXT；挑战发布不等于已签发。普通/通配符域名按实际 DNS-01 场景配置，不把一次提供方受理视为证书成功。

批量部署流程：

1. 在台账目标配置服务器、受管服务、握手域名/端口，以及证书和私钥的不同绝对路径；手工维护可同时留空两条路径。
2. 为目标 Agent 明确启用 `certificate_deploy`，在本机和面板同时允许服务与写入目录；默认均关闭。不能写到 Agent 身份、状态、安装路径、系统敏感文件或非普通目录。
3. 选择已保存且有效的证书版本、私钥凭据引用和目标集合。lego 已签发版本可自动关联加密私钥；外部证书只引用凭据中心，不在普通表单粘贴私钥。
4. 核对五分钟预览。现有非司南受管文件必须明确接管，受管文件已被外部修改时拒绝覆盖。确认后逐台排队，部分排队拒绝单独显示。
5. Agent 通过设备身份接口仅在内存取得材料，检查证书/私钥匹配，写入受管路径，按服务组保护私钥，重载服务并检查运行状态。失败恢复旧文件内容、属主和权限后重载；无法确认恢复则明确失败。受控本机恢复副本为 0600。
6. 从面板单独发起真正 TCP/TLS 握手，检查域名、信任链和期望叶证书指纹。验证不依赖 HTTP 协议，只向固定解析后的公共地址连接；预发布证书信任失败是预期结果。文件部署、服务重载与实际握手分别记状态。

未知部署可走共用任务的独立只读核对：新 Agent 观测读取公开证书指纹和服务状态，保留原部署回执；不下载私钥，不重放写入。实际外部握手仍需单独验证。

## 端点、转发与隧道

### 服务器替换与网络业务迁移

网络配置页提供独立服务器替换助手。明确选择原服务器、替换服务器和1–64个受影响对象，逐项预览域名关联、证书服务/目录/握手目标、端点公开地址、转发监听与实际目标、系统参数及规则的差异。可以明确替换新设备上的监听地址、端口、服务与证书路径；不允许在迁移里隐式添加其他服务器、改签发凭据、删除覆盖域名或修改未选择的证书目标。DDNS规则保持原引用并给出单独规则迁移入口，不把域名关联改变当成已经改了DNS解析。

五分钟持久预览冻结原配置摘要/版本、活动证书版本与SAN、关联域名/规则/账号版本、凭据引用元数据，以及两端Agent公开身份摘要、平台、地址、能力、面板授权和生命周期。目标未启用相应能力、证书服务/目录未授权、固定监听地址未在目标观测到、证书过期/SAN不匹配、已有或所选受管监听冲突、引用凭据停用、正在签发或存在未确认部署，均产生阻断项。真实监听检测仍需独立Agent观察与应用时核对；没有观察不宣布端口空闲。

确认需要原发起管理员的近期会话证明，再检查两端及所有关联对象的当前权限，事务中重新构造并比对完整预览，版本/能力/账号/目标冲突改变即拒绝。普通网络业务保留对象标识、证书版本和变更历史，仅改变所选业务目标配置。WireGuard及SSH隧道产生新对象UUID的候选并保留原对象，新设备在后续明确部署时独立生成本机密钥；不读取或复制源设备的独立私钥。隧道候选默认禁用，须在中转重新授权新公钥；WireGuard还须明确停止旧地址并更新对端成员后再启用。

保存迁移配置不派发任务、不停止旧服务，也不产生部署或连通性成功。界面分别标明新目标待部署、待实际验证、源服务清理待确认，并保留迁移预览结果及可审计历史。之后使用已有受管执行、证书部署、真实TLS握手和网络探测流程；原Agent身份与新Agent身份保持独立。

接口为 `GET .../server-migrations/candidates`、`POST .../server-migrations/preview`、`GET .../server-migrations/{id}`、`POST .../server-migrations/{id}/apply`（均在 `/api/network-configuration` 下）。候选先按原服务器关联缩小查询，不将数据库故障当作没有对象；预览及应用只接受管理员会话。历史读取也重新核对预览时两端及关联对象范围。

端点台账分别保存本机监听、公开地址、端口、协议、责任方。外部 NAT 仅登记已授权关系；司南不伪造外部部署结果。关系图箭头表示配置关系，观测缺失时标未验证。

受管 TCP/UDP 转发使用安装好的 socat 与 systemd，支持 IPv4/IPv6 独立监听和目标。面板检查现有及待部署受管监听重叠，Agent 再通过 `ss` 核对实际监听；UDP 不复用已有监听。服务状态、日志和端到端探测复用共用服务器/诊断入口。当前转发是临时服务，重启后需重新核对和明确启动；没有工具时拒绝，不自动安装。

反向隧道使用 OpenSSH 发布明确 TCP 目标，使用独立本机 ed25519 隧道密钥，必须在中转端预先授权公钥并填写固定主机公钥。严格主机校验、批处理、转发失败退出和保活均显式配置。初始执行器只接受明确 IPv4 中转/目标；监听公网范围还受中转 `GatewayPorts` 与授权限制。服务运行不代表外部端口可达。UDP 反向隧道与 frp 没有伪装成此 TCP 能力。

私有组网使用 WireGuard：手工指定私有地址、端口、成员公钥、允许 CIDR、端点与保活；禁止默认路由和公有网段，私钥留本机。应用保存前一受管配置及原激活状态，失败恢复；可独立停止、回退或启用开机。只读状态只读取公开公钥、握手时间和传输，既不生成密钥也不返回私钥。该能力管理现有声明成员，不自动发现或为其他成员部署配置。

## 网络参数与防火墙

只读盘点显示实际拥塞算法、可用算法、队列、缓冲区、连接跟踪、端口范围和工具可用性；没有值保留采集错误。BBR 只有实际可用列表里存在才允许选择。

参数模板采用有界白名单和逐项用途，修改预览不执行。临时应用先保存原值与恢复脚本，成功安排本机独立 systemd 恢复计时器后才写入 sysctl。确认真实结果后解除计时器，再单独保存长期配置。持久化只修改 `95-sinan-network.conf` 受管文件，合并既有参数并备份旧文件；回退先比对当前受管文件，拒绝覆盖外部修改。调优效果应复用相同来源、目标、参数和时长的诊断报告比较，不承诺一定变快。

受管防火墙使用 nftables 独立 `inet` 入站表，显式声明源 CIDR、TCP/UDP、端口、accept/drop 以及管理 TCP 端口。保留回环、已建立连接和管理端口；不删除、重写外部规则。临时执行前真正 `nft -c`，安排本机恢复再应用；确认与持久化单独操作，持久化生成明确受管文件和 systemd 服务。其他表仍能阻断连接，恢复不能保证覆盖外部防火墙、路由、掉电等故障。
